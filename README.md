# Stream Overview PH

A music-stream analytics platform tracking Spotify (via a linked Stats.fm
account) and Apple Music (via a linked Musicat account — https://musicat.fm),
with a public Philippines-wide dashboard and a private personal dashboard.

Each user can link one Stats.fm account (Spotify) and one Musicat account
(Apple Music) independently — either on its own, or both at once. Apple
Music data is pulled exclusively from Musicat; Stats.fm is never used for
Apple Music, even though Stats.fm itself supports it.

> **Musicat API note:** musicat.fm doesn't publish public developer API docs
> at the time this was written. `app/Services/MusicatService.php` and
> `config/musicat.php` are written to the same shape as the (documented)
> Stats.fm integration, but the actual endpoints/response fields are
> placeholders — confirm the real API surface with Musicat before relying on
> this in production.

## ⚠️ How this codebase was produced — read this first

This was hand-written as a complete set of **application-layer files**
(models, controllers, services, migrations, React pages/components) — it was
**not** generated by running `laravel new` / `composer create-project` /
`npm create vite` in a live environment, because the sandbox this was built
in has no network access and can't install PHP/Node dependencies or hit the
real Stats.fm API. That means:

- The Laravel side has all of *your* app code (routes, controllers, models,
  migrations, config) but is missing the boilerplate framework files a fresh
  `laravel new` install generates (`artisan`, full `bootstrap/`,
  `storage/`, default `config/*.php` files, etc.).
- The React side has all of the actual UI code but is missing the
  `package-lock.json` / installed `node_modules`.
- Nothing here has been executed or tested against a real server — treat it
  as a very complete first draft, not a verified build.

**For an app this size, you'll get a much smoother result actually running
and iterating on it inside [Claude Code](https://claude.com/claude-code) or
Claude Desktop's Code tab**, where Claude can install dependencies, boot both
servers, hit real errors, and fix them live. Happy to keep going that route
if you'd rather not do the merge step below yourself.

## Setup (manual path)

### 1. Backend (Laravel 11)

```bash
composer create-project laravel/laravel backend-fresh
```

Then copy this repo's `backend/app`, `backend/database`, `backend/routes`,
`backend/bootstrap/app.php`, and `backend/config/{statsfm,sanctum,cors}.php`
into `backend-fresh`, overwriting the generated defaults where they collide.

```bash
cd backend-fresh
composer require laravel/sanctum
cp ../backend/.env.example .env
php artisan key:generate
# set your DB credentials + STATSFM_API_KEY in .env, then:
php artisan migrate
php artisan serve   # runs on http://localhost:8000
```

To keep listening data fresh automatically:

```bash
php artisan schedule:work
```

You'll need a Stats.fm API key from their developer portal
(https://beta.docs.stats.fm/) — set it as `STATSFM_API_KEY` in `.env`.

### 2. Frontend (React + Vite) — port 5180

```bash
cd frontend
npm install
cp .env.example .env
npm run dev   # runs on http://localhost:5180, pinned via vite.config.js
```

## How the account model works

- Users register/log in (Laravel Sanctum token auth) before connecting
  anything.
- Each user may link exactly **one** Stats.fm account
  (`statsfm_connections.user_id` is unique, and a given Stats.fm account can
  only be claimed by one local user).
- That one connection is the source for both Spotify and Apple Music data,
  since Stats.fm itself aggregates both.
- The public landing dashboard only aggregates plays from users who left
  `include_in_public_overview` on (default: on) — nothing private leaks in
  unless someone chooses to contribute to the PH-wide numbers.

## Project structure

```
backend/    Laravel API — auth, Stats.fm connection, personal + public stats
frontend/   React (Vite) — landing dashboard, auth, connect flow, personal dashboard
```
